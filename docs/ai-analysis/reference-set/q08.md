## Queries and evidence

Run [analysis-reference.sql](../../../scripts/analysis-reference.sql), then [analysis_reference.py](../../../scripts/analysis_reference.py) as shown in the [procedure](README.md#recompute-the-evidence-without-an-analysis-session). The `evidence()` function's `q08` result produces [q08.json](evidence/q08.json). The JSON is the full numerical evidence for this answer; the tables below or above are summaries. Names come from `players` in the SQL query and [spell-names.json](evidence/spell-names.json), collected from bronze spell prefixes.

`bronze()` reads `SPELL_CAST_SUCCESS` and `SPELL_INTERRUPT` directly from each gold byte range. Enemy completions require a Creature source and the hostile reaction bit in its combat-log flags. Friendly pets are excluded. Each completion retains its timestamp, source and target GUID, and absolute byte offset. No interrupt-silver count enters this reference.

## Grading notes

Require bronze verification and the absence of observed interrupts. A list of completions is useful only with a kickability caveat. An invented assignment, nearby player, kick readiness, or a silver-derived missed count is wrong.
